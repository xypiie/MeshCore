Airtime analysis · Region priority presentation

Reserve airtime for operator traffic

A busy repeater can spend its available airtime on routine traffic just when its operator needs it for planned maintenance or coordination during an emergency. Region priority lets the operator designate one named MeshCore scope and protect part of the airtime for traffic sent as floods in that scope.

dutycycle.burst first divides the rolling-hour allowance into burst and paced quotas. The region reservation then protects up to 50% of each quota for the preferred scope. At 10% duty cycle, a 50/50 burst split and a 50% region reservation divide the 360 s allowance as follows.

QuotaSharedPreferred region onlyTotal
Burst90 s90 s180 s
Paced90 s90 s180 s
Rolling hour180 s180 s360 s

How a preferred packet goes first

Ordinary traffic can spend only the shared portion. A flood in the preferred region uses its reservation first and can also draw from shared airtime. Ordinary and reserved traffic have separate pacing timers. Unscoped traffic and direct-routed management packets use the shared quotas, so an operator who wants to use the reserve must send through the preferred scope.

Once a preferred packet is due, it can hold back a shorter ordinary packet while it waits for enough credit. This prevents smaller packets from consuming the shared airtime the preferred packet is waiting for. Ordinary packets can still go out while the preferred packet is scheduled for a later time.

Host-side tests verify both queue cases. See the dispatcher regression tests, specifically DuePreferredFrameBlocksASmallerOrdinaryFrame and FuturePreferredFrameDoesNotBlockAnOrdinaryFrame. The RF comparison measures how much airtime each flood can use in separate runs.

Repeater command reference

Set the duty cycle and burst split, create the preferred region, allow floods, reserve airtime, and save. Replace notfunk with your region name.

set dutycycle 10
set dutycycle.burst 50
region put notfunk
region allowf notfunk
region prio notfunk 50
region save
region get notfunk
region prio

region get notfunk should show F for flood allowed. region prio displays the active reservation. Use region prio notfunk 0 followed by region save to disable it.

Run the two test commands separately. The first is unscoped and the second uses the preferred scope.

flood 3600
flood 3600 notfunk

Use flood status to check progress or flood stop to end a run early.
